Step 1 - Who holds each role?

Policies name roles, not people. This tab simulates User Administration: it assigns a demo user to each role for a client or account. Real sign-in and role enforcement are not implemented.

Step 3 - Start a workflow for a business step

The chain is resolved from the client, account, and business step: that step's override if there is one, otherwise the default chain. You never re-enter approval stages.

Select or save a policy first.

One reusable approval engine

ApprovalChain coordinates the stages; each reviewer gets an internal ApprovalStep. A single reviewer and a multi-stage sign-off use the same engine. The parent applies the final result once all required steps finish.

Step 4 - Approve, return or reject

Each block is one workflow with its full approval chain. Rows in the same stage run in parallel; the next stage unlocks only after every row in the previous stage approves. A rejection, return or timeout ends the plan and stops the remaining rows.
